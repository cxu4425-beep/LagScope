## 中文

### 🔒 診斷資料不再帶 Wi-Fi 名稱、路由器位址和帳號名稱

系統匣「複製診斷資訊」那一份,本來就是設計來貼到問題回報裡的 —— 結果它帶著:

- 你的 **Wi-Fi 名稱**
- 路由器的 **MAC 位址**
- `C:\Users\<帳號>\AppData\...` 裡的 **Windows 帳號名稱**

自我檢測早就修成「沒有 Wi-Fi 名稱、沒有帳號」,旁邊這份診斷資料卻從沒被同樣對待過。

現在:

- 無線只留 **頻段和訊號強度**,顯示成 `Wi-Fi (5 GHz)`;MAC 位址拿掉。
- 設定資料夾的路徑跟自我檢測一樣,帳號名稱換成 `%USERPROFILE%`。
- 報告和歷史視窗裡的無線比較,改用 **「Wi-Fi A (5 GHz)」** 這種代號。
  同一台路由器的兩個頻段**共用一個字母** —— 因為「同一個網路換另一個頻段」正是這個比較要給你的建議。
- 診斷資料順便補上了 4.12.0 新增、但這裡漏掉的「目前有量不到的東西」。

### 🔁 不能再拿 LagScope 量它自己

那份資料監看的程式是 `LagScope.exe` 本身。它的連線**只有它自己的測量** ——
所以量的瞬間它最忙(於是在程式清單裡排很前面,很容易被選到),兩次測量之間它一條連線都沒有。
量出來的每個數字,都是「測量的測量」;那 13% 的「沒有連線」也是這樣來的。

現在程式清單**不再列出 LagScope 自己**(包含單檔版啟動時的那個外殼行程)。
如果你之前已經選了它,會直接顯示:

> 正在測 LagScope 自己——它的連線只有它自己的測量。請在設定裡選要測的程式

### 🖥️ 顯示延遲是猜的時候,現在會說

那份資料裡更新率和畫格時間都是空的 —— 顯示延遲那 25 ms 是**照 60 Hz 猜的**,
但新的「目前有量不到的東西」**什麼都沒說**。
程式把預設的 60 Hz 當成「系統回報的數字」了,剛好把這一項存在的意義整個藏起來。

而它會是空的原因:浮窗**被顯示出來時**才去讀螢幕更新率。只開在系統匣、浮窗藏起來的話,就永遠不會讀。

現在啟動時就直接問螢幕;浮窗出現時再用它所在的螢幕修正。
真的問不到,面板就會老實說是猜的。

## English

**The diagnostics dump no longer carries the Wi-Fi name, the router's MAC
address or the Windows account name.** The block the tray menu copies exists to
be pasted into a bug report, and it carried all three. The self-test had long
since been made to promise "no Wi-Fi name, no account"; the dump next to it never
got the same care. It now keeps the band and signal only, redacts the account
from the config path, and gains the health list it was missing. The wireless
comparison in the report and history window labels links "Wi-Fi A (5 GHz)" -
one letter per router, because "the same network on the other band" is the
advice the comparison exists to give.

**LagScope can no longer be set to measure itself.** Its connections are its own
probes: busiest exactly while measuring, which puts it near the top of the app
list, and idle in between - the source of that dump's 13% "no connections". The
list no longer offers it (including a one-file build's launcher process), and a
target saved before this says so plainly.

**A guessed display delay now says it is a guess.** The 60 Hz default was being
counted as a reported refresh rate, hiding exactly the case the health entry
exists to show. It was empty in the first place because the overlay only reads
the refresh rate when shown; run from the tray, it never is. The primary screen
is now asked at start-up.

761 tests green.
