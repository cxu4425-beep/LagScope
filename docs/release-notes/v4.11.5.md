## 中文

### 🔑 配對:存取碼送錯了參數名

桌面伺服器讀的是 `key`,手機組出來的是 `code`。

配對畫面上有兩個欄位:**「電腦的網址或 IP」**和**「存取碼」**。分開填 —— 那是看到那兩個標籤
之後最自然的動作 —— 會產生 `?code=1234`,伺服器回 403,網頁顯示「访问码不对」。

```
手機組出:  http://192.168.0.10:23125/?code=1234   ✗ 403
伺服器要:  http://192.168.0.10:23125/?key=1234    ✓
```

**整段網址貼上剛好可以用**,因為那串本來就帶著 `key=`。而那正是畫面提示裡寫的做法 ——
所以**被寫進說明的那條路,剛好是唯一避開這個 bug 的路**。

現在兩邊各自只宣告一次(`Pairing.QUERY_KEY`、`web.ACCESS_QUERY`),並且新增一個測試
**同時讀兩個檔案**,斷言參數名、連接埠、端點都一致。

那個測試才是重點:Java 那套測試和 Python 那套測試**各自都完全自洽** ——
這正是它能活這麼久的原因,因為誰都看不到電線的另一頭。

### ⚠️ 安裝完按「直接開啟」會跳安全性錯誤

```
Security validation failure: parent process has different executable!
```

跟 v4.8.2 同一句話,**但成因不同**。

`launch_installer` 呼叫 `Popen` 時沒有傳 `env=`,所以安裝程式**繼承了執行中 App 的整個環境**,
其中包含 PyInstaller 的 `_PYI_PARENT_PROCESS_LEVEL`。安裝程式再把環境交給它啟動的新 App ——
那個新行程讀到這個變數,認定自己是 onefile 的子行程,於是去驗證父行程是不是同一個執行檔。
它的父行程是安裝程式,當然不是。

從開始功能表開就正常,因為 Explorer 的環境裡從來沒有那個變數。

現在交給安裝程式的環境會清掉 `_PYI_*`(以及 `_MEIPASS2`),**按前綴清而不只是按名字** ——
那些名字會隨版本改，前綴才是契約。

> 我在 v4.8.2 留的註解寫著「安裝程式自己的『立即執行』會正確把它帶回來」。
> 它指向的,正是帶著這個問題的那條路。

## English

**Pairing sent the access code under the wrong name.** The server reads `key`;
the phone built `code`. Filling the two labelled fields separately - the obvious
thing to do - produced a URL the server answered 403 to, shown as "access code
incorrect". Pasting the whole URL worked, because it already carried `key=`, and
that is the path the on-screen hint describes: the documented path was the only
one that avoided the bug.

Both sides now declare the name once, and a new test reads both files and
asserts they agree, along with the port and the endpoint. That test is the
point - the Java suite and the Python suite were each perfectly consistent with
themselves, which is exactly why this survived.

**The installer's "run now" opened a security error.** Same message as v4.8.2,
different cause: `launch_installer` called `Popen` with no `env=`, so the
installer inherited `_PYI_PARENT_PROCESS_LEVEL` and handed it to the app it
launches. That app concludes it is a onefile child and checks its parent runs
the same executable - its parent is the installer. Starting from the Start menu
works because Explorer's environment never had the variable.

The environment is now scrubbed of `_PYI_*` by prefix, not just by name.

694 tests green.
