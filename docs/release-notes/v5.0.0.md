## 中文

### 🌐 新的預設：「我的網路連線」

第一次打開，設定精靈的第一個選項就是它，**直接按「開始使用」就好，什麼都不用填**。

- **延遲**量的是離你最近的公共伺服器——Cloudflare `1.1.1.1`、Google `8.8.8.8`、阿里 `223.5.5.5`、Quad9 `9.9.9.9`
  四個都先量一次，留最近的那個；每半小時、或連續失敗三次就重挑。沒有哪一個位址到處都好：
  8.8.8.8 在中國大陸被擋、223.5.5.5 離歐洲很遠，所以它自己挑。
- **完全斷網時**不會每一輪都把四個重新量一遍（那會讓每一輪卡好幾個逾時），兩分鐘才重試一次。
- 懸浮窗顯示 **下載、上傳、丟包**；精靈還會**自動把你的路由器加進來**——延遲紅了但路由器綠的，
  就是外面的問題；路由器也紅，就是家裡（多半是 Wi-Fi）。

以前沒選東西時，它量的是 `api.live.bilibili.com`、狀態欄寫「未設定房間號」。

### 📏 數字就是 `ping` 會印的那個

網路類的模式（網路連線、任意程式、伺服器位址），大字現在就是**來回時間**，標「實測」。
以前會**另外加上估算的顯示延遲**（約 33 ms）和藍牙耳機延遲——所以 6 ms 的伺服器會顯示 39 ms，
跟電腦上任何其他工具都對不起來。那兩個估算只屬於 B 站直播／影片的「總延遲」（畫面到底晚了多久），現在也只算在那裡。

### 🎨 顏色有兩把尺

以前只有一組門檻：**2000 / 5000 ms**——那是給 B 站直播延遲（秒級）用的。拿去套 ping，**300 ms 也是綠色**，
附加監測的 DNS 180 ms 也綠。

現在網路延遲是 **80 / 150 ms**，B 站維持 2 / 5 秒，附加監測永遠用網路那把尺。設定 → 進階兩組都能改。

### ⚡ 測網速：上傳、還有滿載延遲

以前只測下載。現在：

```
下載速度：94.2 Mbps
上傳速度：21.5 Mbps
閒置延遲：12 ms
滿載延遲：180 ms　（等級 C）
滿載時延遲大增（緩衝膨脹）：家裡有人下載或上傳時，遊戲和通話會卡。路由器開啟 SQM／QoS 通常能大幅改善。
```

**滿載延遲是最有用的一行**：「為什麼家裡有人下載我就卡」的答案，幾乎都是路由器把封包排成長隊（bufferbloat）。
測速時旁邊同時在量延遲，那些封包跟你遊戲的封包排在同一條隊伍裡，所以量到的就是你會遇到的。
A+ 到 F 照公開測試通用的標準打分。

上傳用 Cloudflare 公開測速點、內容是全零的填充資料，用掉一半的流量上限。

### 📊 流量用量

```
今天 ↓1.52 GB ↑231 MB · 本月 ↓34.0 GB ↑5.10 GB
```

托盤選單第一行、托盤圖示提示、延遲歷史、體檢報告都有。整台電腦所有網卡，照你那邊的日期換日換月，
存在 `usage.json`、保留一年多。**只在程式開著時算**，關著的時候不會猜——所以建議開機自動啟動。

### 🧭 介面整理

- **托盤選單**從二十幾個平鋪的項目，整理成：流量 → 測網速／網路體檢／延遲歷史 → 懸浮窗（選項收進子選單）→
  暫停 →「B 站」和「更多工具」子選單 → 設定。
- **設定 → 監測對象**：一般模式在前，B 站的三個標上「B 站：」放後面；**只顯示你選的那個模式需要的欄位**，
  B 站自動偵測那一整塊在其他模式下會藏起來，不再是一整頁灰掉的選項。
- 修掉一個藏得很深的問題：新的「我的網路連線」模式如果沒放進下拉選單，打開設定按確定（例如只是改個主題）
  就會**默默被切成 B 站自動跟隨**。現在每一種模式都有測試「打開設定、按確定、模式不變」。
- 托盤提示、懸浮窗、手機頁面以前各自決定要顯示哪幾行、用哪組門檻上色，已經各自跑掉了；現在都由同一個地方決定。

### 升級的人

**你存好的設定完全不變**——原本跟隨 B 站的，繼續跟隨 B 站。只有全新安裝才會預設「我的網路連線」。
想換的話：設定 → 常規 → 監測對象 → 我的網路連線。

## English

**A new default: your internet connection.** The first-run wizard's first choice; press
Start and nothing needs filling in. Latency is measured to the nearest of Cloudflare
1.1.1.1, Google 8.8.8.8, AliDNS 223.5.5.5 and Quad9 9.9.9.9, re-chosen every half hour or
after three failures - no single address works everywhere. With no network at all a round
costs one timeout, not a survey. The overlay shows download, upload and loss, and the wizard
adds your router alongside: red latency with a green router means the problem is outside.

**The number is what ping prints.** For the internet, an app or an address, the headline is
the round trip, measured. It used to have an estimated display delay (and any headphone
offset) added, so a 6 ms server read 39 ms. Those belong in a Bilibili stream's total, and
stay there.

**Two colour scales.** There was one pair of thresholds, 2 s / 5 s, built for stream delay;
on a ping, 300 ms was green. Network latency is now 80 / 150 ms; side watches always use it.

**Speed test: upload and latency under load.** Download, upload, idle and loaded latency,
graded A+ to F. The loaded figure answers "why does everything lag when someone downloads":
bufferbloat, usually fixed by SQM / QoS on the router.

**Data usage**, today and this month, at the top of the tray menu, in the hover text, the
history window and the report. Every adapter, local days, counted only while running.

**Tidier UI.** The tray menu is grouped (usage; speed test, diagnosis, history; overlay;
Bilibili and More submenus). Settings lists the general modes first and shows only the chosen
mode's fields. Fixed: a mode missing from the settings dropdown would have been silently
replaced the next time someone pressed OK; every mode now has a round-trip test.

**Upgrading:** saved settings are untouched. Only fresh installs default to internet mode.
